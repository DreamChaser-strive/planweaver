# PlanWeaver 安装与发布步骤

> 本文档区分三类动作：**你能在本地做的**、**需要在 WorkBuddy 客户端点选的**、**需要在开放平台后台完成的**。
> 任何一步我没有实际执行，都会明确标注"未验证"。

## 一、先替换作者信息（必做，当前唯一阻断项）

当前 `SKILL.md` 的 `author` 仍是占位符 `待填写（发布者名称）`。用一条命令写入真实名称：

```bash
cd <项目根目录>
python tools/build_release.py --author "你的名字或公司名" --both
```

这条命令会：
1. 运行全部测试（105 项，失败即中止打包）；
2. 把作者写进**四处**：`SKILL.md` 的 `author`、`LICENSE` 的著作权人、`README.md` 的作者行、`release/MARKETING.md` 的发布者；
3. 构建后自检四处是否一致，不一致直接报错退出；
4. 在 `dist/` 生成 `planweaver-1.0.0.zip` 与 `-flat.zip`。

替换后用审计工具复核：

```bash
python tools/audit_package.py --zip dist/planweaver-1.0.0.zip
```

预期：`检查项 34 个 | 通过 33 | 警告 1 | 失败 0`（那 1 个警告是 `category` 需后台确认）。

> 已实测：用 `--author "发布者名称测试"` 构建时，四处均被正确写入且一致性检查通过；随后已还原为占位符版本，避免留下虚构作者。

## 二、本地安装测试（WorkBuddy 客户端）

### 方式 A · 导入 ZIP（推荐，最接近用户路径）

1. 打开 WorkBuddy → 左侧菜单「专家 · 技能 · 连接器」→「技能」
2. 点右上角「添加技能」→ 选择导入本地 ZIP
3. 选 `dist/planweaver-1.0.0.zip`
4. 确认解析结果：名称 `PlanWeaver 全域智能规划师`、版本 `1.0.0`、分类显示正常
5. 安装后新建对话，输入测试语句

**如果提示解析失败**：说明平台对 ZIP 顶层结构的要求不同。改用扁平包：

```bash
python tools/build_release.py --author "你的名字" --flat
```

扁平包的 `SKILL.md` 直接位于 ZIP 根目录。两种包内容完全一致，只是层级不同。文档未明确要求哪一种，先试带目录的（与官方结构图 `{skill-name}/SKILL.md` 一致）。

### 方式 B · 放入用户技能目录

```bash
# macOS / Linux
cp -r planweaver ~/.workbuddy-ai/skills/

# Windows（Git Bash）
cp -r planweaver "C:/Users/<你>/.workbuddy-ai/skills/"
```

重启客户端后应出现在技能列表。

### 安装后的验收对话

完整版（8 个场景，含预期行为、验收标准、失败排查路径）见 **`release/ACCEPTANCE-TESTS.md`**，可直接复制执行。
下面是 3 分钟速查版：

| # | 输入 | 期望表现 | 关键判断点 |
|---|---|---|---|
| 1 | `帮我规划一下：三个月内考过雅思 6.5，同时 11 月中要交付一个项目，每周还想运动三次。我每周大概 15 小时。` | 输出九段式完整方案，含"有效可用 vs 需求"的具体数字 | 有没有算总账；有没有给三方案；有没有说"紧张/可行/不可行" |
| 2 | `我落后三天了，帮我重排一下。` | 先算影响域，可能回答"不需要改排期"，并列出不变的任务 | **绝不能**把全部任务整体后移 |
| 3 | `考证和项目撞了，时间只够一个。` | 给 2–3 种分配方式对比 + 让你选 | 不能替你拍板 |

**附加压力测试**：

- `我每天只有 2 小时，但要 4 周学完三门课并通过考试` → 应明确说不可行，给四类出路
- `帮我把所有任务都往后推三天` → 应先问"哪些真的受影响"，而不是照做

### 3.3 提交步骤

1. 登录开放平台 → 进入「技能」
2. 创建 / 上传，提交 `dist/planweaver-1.0.0.zip`（解析失败再换 `-flat.zip`）
3. 平台解析 `SKILL.md` frontmatter，自动填充名称、版本、描述
4. 补齐后台字段：
   - **分类**：按后台下拉选最接近的一项（YAML 写的 `capability` 仅供参考）
   - **服务类目**：按后台枚举选
   - **头像**：上传 `release/avatar-512.png`
   - **介绍 / 一句话简介 / 使用示例 / 隐私说明**：从 `release/MARKETING.md` 对应章节复制
5. 检查预览：名称、简介、文件树是否正常
6. 提交审核
7. 等待结果（以平台通知为准）
8. 审核通过后发布上线；在后台查看运行数据并维护版本

## 五、回滚与维护

- **撤回**：后台技能管理页可下架；已安装用户不会自动卸载，需在版本说明里提示。
- **升版本**：改 `SKILL.md` 的 `version` 与 `CHANGELOG.md`，重跑
  `python tools/build_release.py --author "..."`，得到新 ZIP 后提交新版本。
- **状态文件兼容**：`schema_version` 主版本变化时校验器会直接报错，不做静默兼容；升级前请备份用户的 `plan-state.json`。
