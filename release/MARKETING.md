## 二、一句话介绍

**把学习、工作、生活放进同一本时间账本，先算清到底做不做得到，再排计划；情况变了，只改真正受影响的部分。**

英文：One ledger for every goal — check feasibility before scheduling, and when things change, replan only what is affected.

## 三、详细功能介绍

多数计划失败不是因为不会拆任务，而是两件事没做：

**一是没算总账。** 学习、工作、生活各排一份，每份都"看起来合理"，合起来每周 40 小时——从第一周就不可能执行。

**二是一有变化就推倒重来。** 落后三天，把整张表往后挪三天。本不需要改的任务被改了，硬截止被无声突破，用户看着全变的表格，干脆放弃。

PlanWeaver 针对的就是这两个问题。

### 会先算账，再排期

把所有目标放进一份资源账本：`有效可用 = 周可用时间 × (1 − 缓冲比例)`，与所有未完成任务的工时对比，给出三档判定：

- **可行**：保守估算都在容量内，可以按标准方案承诺
- **紧张**：通常估算在容量内、保守估算超出，只能承诺保底成果，并设置检查点
- **不可行**：直接说不行，给出四类出路（缩小范围 / 延长周期 / 增加资源 / 调整优先级）

不用"提高效率""挤一挤"掩盖资源不足，也不靠压缩睡眠和休息来让计划"看起来成立"。

### 给出三种真正不同的方案

保底、标准、冲刺——差别在**目标范围与验收标准**上，不是每天多排两小时。冲刺方案只在你确实有额外时间/预算/帮手时才提供。

### 变化发生时，只改该改的部分

你说"我落后了三天"，它会：

1. 算这次变化真正影响哪些任务（直接受影响 + 依赖它们的下游任务）
2. 检查这条链上还剩多少余量
3. 余量够 → **计划根本不用改**，只更新进度
4. 余量不够 → 按 S0 吸收 → S1 重排 → S2 压缩 → S3 降级 → S4 延期 → S5 增资源/放弃 逐级尝试，能停在前面就不跳到后面
5. 明确告诉你**哪些安排保持不变**，哪些改了、为什么改

### 另外还能做

- **"我现在该做什么"**：结合剩余时间、截止、依赖，给一个动作 + 理由 + 一个"先不做"
- **多目标抢时间**：给 2–3 种分配方式的收益/代价/风险对比，由你选
- **周/月复盘**：计划 vs 实际，按"拆分 → 估算 → 前置 → 资源 → 外部事件 → 执行波动"顺序归因，不把一切归咎于"你不够自律"

### 自带确定性校验脚本

内置两个 Python 脚本（仅标准库、无网络请求）：

- `validate_plan.py`：算周容量是否超载、依赖是否成环、前置截止是否晚于后继、硬截止累计负荷是否成立、任务时间块是否撞上固定日程或休息时段，以及**这次重规划是否在机械顺延**（用依赖图可达性判断被移动的任务是否真的受影响）
- `plan_tool.py`：建档、更新进度、记录重规划、导出状态；写前自动备份

## 四、四大适用领域

| 领域 | 典型目标 | PlanWeaver 具体做什么 |
|---|---|---|
| **学习** | 考试备考、课程学习、技能提升、长期学习路线 | 把"提高英语"编译成可验收目标（考试/阅读/口语/写作对应不同结构）；排阶段模考节点；与工作时间抢池子时给取舍 |
| **工作** | 项目交付、任务优先级、职业发展 | 按硬截止倒排关键路径；识别前置未满足的任务；新增临时任务时算清它挤占谁 |
| **生活** | 日常事务、习惯养成、个人时间 | 把运动/睡眠设为不可侵占的受保护时段；习惯类目标按"可持续"而非"冲刺"排 |
| **长期目标** | 数月到数年的目标拆解、阶段成果、能力积累 | 阶段里程碑 + 验收标准；每阶段结束做偏差校准，修正下一版估算 |

跨领域协调是默认行为：四个领域的任务进**同一份容量模型**，不生成互相冲突的多份计划。

## 五、五项核心机制

1. **全域资源账本**
   学习/工作/生活共用一份时间池。账本含可用时间、固定安排、弹性任务、精力分布、预算、必须保留的休息、缓冲。
   纪律：排期用"通常估算"，承诺用"保守估算"——同时避免过度乐观和过度保守。

2. **目标编译器**
   模糊愿望 → 目标名、预期成果、可验证的完成标准、截止日期与刚性、当前进度、前置条件、任务与依赖、三点估算、主要风险、下一步。
   例："学完一章"不合格；"能独立做 3 道真题且正确率 ≥ 80%"合格。

3. **多路径规划（保底/标准/冲刺）**
   差异落在目标范围、验收标准、优先级上。保底方案的任务量通常只有标准的 50–65%，而不是"标准打个折"。

4. **变化影响分析与动态重规划**
   四类影响域：直接受影响、下游闭包、资源冲突、里程碑。其余冻结并在输出中明确列出"以下安排不变"。
   六级策略阶梯，每级有前置条件与上限（如 S2 压缩单任务 ≤ 15%，且不碰睡眠/休息/用餐）。

5. **计划校准**
   偏差系数 `k = 实际耗时 ÷ 预估耗时`，按任务类别累计；样本 < 3 只提示趋势、不给系数。
   归因顺序固定，最后才考虑执行波动。结论必须落到下一版计划的至少一项改动（估算乘子/颗粒度/缓冲/任务上限）。

## 六、三个代表性使用示例

### 示例 1 · 学习 + 工作 + 生活三线并行

**输入**：
> 我想三个月内把雅思考到 6.5，手上还有个项目 11 月中要交付，另外想每周运动三次。我每周大概能挤出 15 小时。

**输出要点**（真实计算口径）：
```
有效可用 = 900 × (1 − 0.15) × 12 周 = 9,180 分钟
需求（通常）= 3,240 + 1,980 + 1,620 = 6,840 分钟（占用率 74%）
需求（保守）≈ 9,240 分钟

判定：紧张 → 可推进标准方案，但只能承诺保底成果，第 6 周设检查点
推荐：标准方案（项目提前 1 周提测，避开第 9–11 周三线重叠）
放弃：雅思写作单项 6.5，只保总分
不换的：睡眠 7.5 小时/天、每周半天无任务
```

### 示例 2 · 落后三天，但**不需要改计划**

**输入**：
> 我落后三天了，帮我重新排一下。

**输出要点**：
```
受影响：T2 分析结论（直接）、T3 撰写初稿（下游）
不变：T4 用户访谈、T5 竞品分析、T6 附录整理、T7 英语听力（全部按原排期）
余量：T2 还有 3.1 天 ≥ 3 天延迟 → S0 吸收，排期不变
另发现：T3 余量 -0.3 天（延期前就偏紧），需单独提前或拆分
```

**这是与普通待办工具最直观的差别**：它不会把 7 个任务一起后移三天。

### 示例 3 · 两个目标撞车，时间只够一个

**输入**：
> 考证和下个季度的项目撞了，两个都想做，时间只够一个。

**输出要点**：
```
需求 100 小时 / 可用 102 小时（98%）→ 判定：真冲突，不是排序问题

| 分配 | 考证 | 项目 | 风险 |
| A 全给考证 | 标准完成，余 10h | 延期 3–4 周 | 项目信誉受损 |
| B 6:4 | 保底（砍模拟题） | 仍不够，需延 1 周 | 两边都不达标，最差 |
| C 分阶段 | 前 6 周 30h | 延 2 周，保住核心 | 最后两周压力大 |

判断：B 最差；A 与 C 的差别在"你更怕哪件事出问题"。
若项目日期可谈，C 的风险会大幅下降——这是唯一能同时保住两边的路径，但需要你去谈。
```

## 七、适用人群与使用边界

### 适合

| 人群 | 场景 |
|---|---|
| 备考者 | 考试 + 工作 + 生活三线并行，需要判断"到底来不来得及" |
| 职场人 | 项目交付期撞上个人目标，需要取舍而不是硬扛 |
| 多目标并行者 | 同时推进 2–3 个长期目标，需要一个统一时间池 |
| 长期项目负责人 | 需要阶段里程碑、验收标准与变化后的重排 |
| "计划做完就废"的人 | 需要偏差记录与下一版估算修正 |
| 被"落后了"困住的人 | 需要知道哪些其实没受影响，不必全盘重来 |

### 边界（明确不做）

- **不接日历/邮件/第三方 API**：不读写你的日历，不发消息、不下单、不预约。所有输出是文本或本地文件，需你自行落到日历。
- **不做自动监控**：不会后台盯着你的进度、不会自动发现你落后。
- **不做主动提醒**：不会定时推送、不会弹通知。什么时候用，由你发起。
- **不做跨设备同步**：状态文件在你本地，换设备需手动导出/导入。
- **不替你决定人生优先级**：多目标冲突只给可比较的取舍；放弃目标必须你确认。
- **不承诺结果**：不保证"你一定能考过/一定交付"。
- **不适合**：只要一次性建议、想要精确到分钟的日程表、希望 AI 替他决定放弃哪个目标的人。

## 八、版本说明（1.0.0）

首个可发布版本，聚焦"独立、可移植的规划核心"，刻意不接外部服务，以降低权限与审核复杂度。

**包含**：五项核心机制、七种工作模式（全面规划/快速决策/每日安排/进度更新/动态重规划/目标冲突协调/阶段复盘）、2 个仅依赖标准库的脚本、5 份参考文档、4 个可直接使用的模板、105 项自动化测试。

**不含**（后续版本考虑）：日历双向同步、多人协作、跨计划资源统筹、自动提醒。

**已知限制**：关键路径为简化模型（工时求和折算天数）；任务只填到"周"时只能校验周容量；偏差系数需 ≥3 条同类样本才启用。

## 九、隐私与数据处理

这一节可以直接作为平台的隐私说明提交。

| 项目 | 说明 |
|---|---|
| 是否联网 | **不联网**。两个脚本无网络请求代码，Skill 不调用任何第三方 API。 |
| 数据存在哪 | **只在你的本地**。状态保存在你自己指定的目录（`plan-state.json` / `plan-overview.md` / `change-log.md`）。 |
| 是否上传 | **不上传**。没有云端存储、没有账号体系、没有遥测。 |
| 收集哪些信息 | 只收集规划必需的信息：目标、期限、可用时间、任务与依赖、进度与耗时。 |
| 不收集什么 | 不要求账号密码、密钥、身份证、病史等敏感信息；不主动索取与规划无关的个人信息。 |
| 是否会写外部系统 | **不会**。不创建/修改日历事件，不发送消息，不执行任何外部操作。 |
| 数据删除 | 删除本地状态目录即彻底删除；写入前生成的备份在同目录 `backups/` 下，一并删除即可。 |
| 分享给他人的风险 | 状态文件含你的目标与时间安排，转发前请自行确认内容。 |
