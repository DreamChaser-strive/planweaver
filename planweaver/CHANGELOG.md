# Changelog

本文件记录 PlanWeaver 的版本变更。格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循语义化版本。

## [1.0.0] - 2026-10-19

首个可发布版本。范围限定在"独立、可移植的规划核心"，不接第三方 API、日历或邮箱。

### 新增

**五项核心机制**

- 全域资源账本：学习/工作/生活共用一份时间池；有效可用 = 周可用 × (1 − 缓冲)；输出可行 / 紧张 / 不可行三档判定，并强制区分"排期用通常估算、承诺用保守估算"。
- 目标编译器：模糊愿望 → 目标名、成果、可验证完成标准、截止与刚性、进度、前置、任务与依赖、三点估算、风险、下一步。
- 三方案：保底 / 标准 / 冲刺，差异强制落在目标范围与验收标准上，而非任务数量；冲刺方案有准入门槛。
- 变化影响分析与动态重规划：直接受影响 + 下游闭包 + 资源冲突三类影响域计算；S0 吸收 → S1 重排 → S2 压缩 → S3 降级 → S4 延期 → S5 增资源/放弃 的六级阶梯；冻结不受影响的任务。
- 计划校准：偏差系数按任务类别累计（样本 < 3 不给系数）；六步归因顺序，最后才考虑执行波动。

**七种工作模式**

- A 全面规划（九段输出）、B 快速决策（L1）、C 每日安排、D 进度更新、E 动态重规划（七段输出）、F 目标冲突协调、G 阶段复盘。

**脚本（仅标准库）**

- `scripts/validate_plan.py`：字段/类型/枚举、id 唯一性、引用完整性、依赖环检测、三点估算顺序、前置与截止顺序、周容量超载、固定日程与任务块重叠、受保护时段侵占、单日超 24 小时、进度一致性、硬截止累计负荷、重规划机械顺延检测（依赖图可达性）。退出码 0/1/2，支持 `--strict` 与 `--format text`。
- `scripts/plan_tool.py`：`init` / `update` / `replan` / `add-task` / `summary` / `validate` / `export`；写前自动备份、原子写入、保留未知字段、revision 自增。

**参考文档**

- `references/planning-framework.md`、`references/replanning-playbook.md`、`references/calibration.md`、`references/state-schema.md`、`references/output-examples.md`。

**模板**

- `templates/plan-state.json`（可直接通过校验）、`plan-overview.md`、`weekly-plan.md`、`change-log.md`。

**测试**

- 12 个必测场景（模糊目标、三域并行、超容量、固定日程冲突、前置未完成、非关键/关键延期、新增突发任务、硬截止冲突、提前完成、优先级变更、脏状态）。
- 校验器 47 项单元测试、状态工具 16 项 CLI 测试、包合规 30 项（含作者四处一致性），合计 105 项，全部通过。

**发布工程**

- 构建脚本 `tools/build_release.py`：作者写入 SKILL.md / LICENSE / README / MARKETING 四处并自检一致性；默认剔除 `tests/`；支持 `--flat` 与 `--with-tests`。
- 审计脚本 `tools/audit_package.py`：对 ZIP 做目录结构、frontmatter、引用完整性、缓存/临时文件、密钥与个人信息、依赖纯净度、作者一致性的逐项检查。
- 头像生成脚本 `tools/make_avatar.py`：纯标准库绘制 512×512 PNG，不依赖外部图片工具。

**修复**

- `LICENSE` 无扩展名导致构建时漏替换作者（早期版本只处理 `.md/.txt/.json`）。
- 作者一致性检查的 LICENSE 正则缺少多行标志，导致误报"找不到作者信息"。
- 余量计算未考虑任务排期周，导致余量被高估（例：排在第 4 周的任务曾算出 23 天余量）。

### 设计决策

- **不做日程表生成器**：任务只排到"周 + 时间块"，不排到分钟。不确定性大时，精确到分钟是假精确。
- **承诺用保守值、排期用通常值**：同时避免过度乐观与过度保守。
- **校验器只判断自洽性**：计划好不好、目标值不值得，由对话判断并标注为判断，不伪装成计算结果。
- **状态文件优先本地**：单文件 JSON，可复制、可导出、可跨会话导入；环境不支持写文件时降级为可复制内容，不声称已保存。

### 已知限制

- 不接日历/邮件/API；不写回任何外部系统。
- 关键路径为简化模型（工时求和折算天数），未计入并行争抢与日历效应。
- 未提供 `blocks` 时只能校验周容量，无法检测具体时段冲突。
- 冲突协调只给取舍选项，不替用户决定人生优先级。

### 未包含（后续版本考虑）

- 日历双向同步（需 OAuth，会显著提高审核复杂度）。
- 多人协作与任务分派。
- 跨计划的资源统筹（当前一次一份计划文件）。
