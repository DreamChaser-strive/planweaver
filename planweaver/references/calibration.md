# 校准与复盘：把偏差变成下一版计划的输入

本文件服务于模式 D（进度更新）与 G（阶段复盘）。

**核心立场：校准的对象是"计划"，不是"人"。** 复盘的第一产出应该是"下一版计划怎么改"，而不是"用户应该更自律"。

---

## 1. 记录什么

每次进度更新，最少记录四项：

| 项 | 来源 | 用途 |
|---|---|---|
| 预估耗时 | `task.estimate.likely` | 基准 |
| 实际耗时 | 用户报告 / `actual_minutes` | 对比 |
| 预估成果 | `task.acceptance_criteria` | 质量对比 |
| 实际成果 | 用户描述 | 质量对比 |

**没有真实记录就不校准。** 不得凭空推断"你这类任务通常会超时 40%"——除非有 ≥3 条同类样本。

---

## 2. 偏差系数

```
k = 实际耗时 ÷ 预估耗时
```

按任务类别聚合（`writing` / `research` / `coding` / `meeting` / `admin` / `practice` / `other`）。

| 样本量 | 结论强度 |
|---|---|
| < 3 | 只提示趋势，**不给系数** |
| 3–5 | 给系数，标注"初步" |
| ≥ 6 | 可用于下一版估算乘子 |

**用法**：下一版计划里，同类任务 `likely_new = likely_old × k`，并在计划中注明"基于 N 次历史记录调整"。

**注意**：k 是类别级平均值，不适用于个别任务。对首次做的任务，k 不可用。

---

## 3. 归因顺序（查到就停）

用户说"没做完"，不要立刻接受"我拖延了"这个解释——那通常是结果，不是原因。

```
1. 任务拆分是否合理？
   → 检查：单个任务是否 > 4 小时？描述是否含糊（"推进项目"）？
   → 信号：任务连续 3 次未完成，且每次都说"不知道从哪下手"

2. 估算是否系统性偏低？
   → 检查：同类任务 k 是否持续 > 1.3？
   → 信号：每次完成都比预估多，且多得很稳定

3. 前置条件是否缺失？
   → 检查：是否在等别人/等审批/等资料？
   → 信号：任务状态长期 blocked，或反复"下次一定"

4. 资源是否冲突？
   → 检查：该周是否同时压了 2 个以上目标？占用率是否 > 85%？
   → 信号：多个目标同时落后，且落后集中在同一周

5. 外部事件是否改变了条件？
   → 检查：生病、加班、家事、突发任务
   → 信号：单周异常，前后周正常

6. 执行波动（最后才考虑）
   → 检查：上述都不成立，且是间歇性而非持续性
```

**禁止**：把归因直接写成"用户自律不足""用户拖延"。若确实是执行波动，也要写成中性描述 + 具体改进动作（"把任务拆成 25 分钟块，先做 1 块"），而不是道德评价。

## 4. 周复盘结构（模式 G，L2）

```markdown
## 本周计划 vs 实际
| 任务 | 计划 | 实际 | 偏差 | 原因类别 |
|---|---|---|---|---|
| T1 数据清洗 | 90min | 150min | +67% | 估算偏低（首次做） |
| T2 访谈 | 120min | 120min | 0 | — |
| T3 报告初稿 | 180min | 未开始 | 未完成 | 前置缺失（等数据） |

## 完成情况
- 完成 2/3，占用率 78%（有效容量 765min，实际投入 270min）
- 里程碑 M1 未达成，缺口 1 天

## 归因
主因：T3 前置缺失（数据未到位），非执行问题。
次因：T1 首次估算偏低 67%，写作/数据类需要乘 1.6。

## 下阶段调整（至少改一项）
1. 估算：数据类任务 likely × 1.5
2. 拆分：T3 拆成"列大纲 / 写 2 节 / 补数据"三步
3. 缓冲：buffer_ratio 0.15 → 0.20（本周被突发事件吃掉 2 小时）
4. 前置：把"数据到位"作为 T3 的解锁条件，未到位不排期

## 下阶段不做
- 不增加新目标（占用率已接近上限）
```

## 5. 月度/阶段复盘（更长的周期）

在周复盘基础上多问三个问题：

1. **目标本身还成立吗？**（外部条件变了？用户兴趣变了？）
2. **优先级需要重排吗？**（哪些目标一直在保底状态？连续 3 周保底 = 该降级或放弃）
3. **能力增长了吗？**（同类任务 k 是否下降？下降说明方法有效）

**结论必须落到状态文件**：更新 `calibration.bias_by_category`、`buffer_ratio`、目标 `weight` 或 `status`，并追加 `change-log.md`。

---

## 6. 复盘的三条红线

1. **不伪造数据**：没有记录就说"数据不足，本次只做定性复盘"。
2. **不制造羞耻**：不用"又没做到""你应该"这类表述。用事实 + 机制改进。
3. **不无限复盘**：周复盘 ≤ 20 行，月复盘 ≤ 40 行。复盘不是写作文。

---

## 7. 早期预警信号

在问题变严重前提示用户（只提示，不制造焦虑）：

| 信号 | 阈值 | 提示 |
|---|---|---|
| 连续落后 | 同一目标连续 2 周未达里程碑 | 建议切保底方案 |
| 占用率过高 | 连续 2 周 > 85% | 建议减任务或加周期 |
| 任务反复阻塞 | 同一任务 blocked ≥ 2 周 | 检查前置，或拆解/替换 |
| 保底常态化 | 连续 3 周只完成保底 | 目标可能定得过高，建议重设 |
| 估算持续失真 | 同类 k > 1.5 且样本 ≥ 3 | 调整乘子，不要靠"更努力"解决 |
